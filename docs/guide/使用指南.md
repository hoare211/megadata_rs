## 一、安装与构建

### 1.1 环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| Python | `>=3.8`（实测 3.12） | `pyproject.toml` 声明 |
| Rust | stable 工具链 | `maturin` 编译扩展 |
| `torch` | `>=2.0` | 仅用于张量/DLPack 与 `IterableDataset` 生态 |
| `pyarrow` | `>=14` | SFT（Arrow IPC）路径 |
| `bbpe_rs` | 自动拉取 | `Cargo.toml` 用 git tag 依赖（`github.com/hoare211/bbpe_rs`），编译时由 cargo 下载，无需手动放置 |
| `bbpe_tokenizer` | 构建数据集需要 | 提供 `tokenizer_path`；并用于 token ID 自动推导 |

可选的开发/测试依赖见 `pyproject.toml` 的 `[project.optional-dependencies].dev`
（pytest / moto[server] / zstandard / numpy / ruff）。

### 1.2 从源码构建

```bash
cd /path/to/megadata_rs

# 1) 建 venv（uv 或 venv 均可）
uv venv --python 3.12 .venv
env -u CONDA_PREFIX VIRTUAL_ENV=$PWD/.venv uv pip install maturin "torch>=2.0" "pyarrow>=14"

# 2) 安装 bbpe_tokenizer（可选：训练/导出分词器时用；扩展编译不依赖它）
env -u CONDA_PREFIX VIRTUAL_ENV=$PWD/.venv \
    uv pip install "git+https://github.com/hoare211/bbpe_rs@v0.1.0"

# 3) 再装 megadata 扩展（cargo 会自动拉取 bbpe_rs v0.1.0 源码）
env -u CONDA_PREFIX VIRTUAL_ENV=$PWD/.venv maturin develop --release

# 4) 自检
.venv/bin/python -c "import megadata, megadata._rust; print('OK', megadata.__file__)"
```

**两个环境坑（照抄上面的命令即可避开）**：

1. `maturin` 在 `CONDA_PREFIX` 存在时会报错 → 必须 `env -u CONDA_PREFIX`；
2. 若机器上配了失效的 http 代理（例如 `git config --global http.proxy`），cargo 下载 crate 会失败
   → 编译时加 `NO_PROXY="*"`（CI 无此问题，不要写进 workflow）。

> `megadata._rust` 是内部模块，业务代码不要直接 import；本文只用 `megadata.*` 公开 API
> （唯一例外是仿真器内部用的 `plan_shard_sequence`，已由 `megadata.simulation` 封装）。

## 二、五分钟上手（用仓库自带 demo 语料）

仓库自带两份小语料，可直接跑通全流程：

| 文件 | 行数 | 格式 |
|---|---|---|
| `data/pretrain_t2t_mini.jsonl` | 20000 | `{"text": "..."}` |
| `data/sft_t2t_mini.jsonl` | 15000 | `{"conversations": [{"role": "user"\|"assistant", "content": "..."}]}` |

### 2.1 构建 PT（预训练）数据集

```python
import os
from megadata import DataBuilder, BatchStream

# bbpe_tokenizer 训练产出的模型目录（用法见 bbpe_rs 仓库 README 的 `bbpe train`）
TOK = os.environ.get("BBPE_TOKENIZER_DIR", "tokenizer")
BATCH_SIZE, MAX_SEQ_LEN = 8, 256                            # 构建与加载必须一致

builder = DataBuilder(tokenizer_path=TOK, max_seq_len=MAX_SEQ_LEN)
builder.build_dataset(
    input_paths=["data/pretrain_t2t_mini.jsonl"],
    output_dir="out/pt",
    mode="pt",
    batch_size=BATCH_SIZE,
    batches_per_shard=16,        # 单个 shard 聚合 16 个 batch（0 = 按 ~128MB 自动）
    compression="zstd",          # 默认即 zstd；"none" 可关
    progress_cb=lambda p: print(
        f"\rshards={p['shards_written']} docs={p['docs_read']} "
        f"{p['bytes_read'] / 1e6:.1f}MB {p['elapsed_secs']:.0f}s", end=""),
)
```

产物（`out/pt/`）：`index.json` + `shard_00000.bin`（+ `.cu` 文档边界 + `.idx` 压缩偏移）。

> **构建端不做数据级去重**：megadata 只做"格式转换 + 装箱 + 落盘"，不识别也不合并重复文本。
> 语料去重（MinHash / 精确去重等）是上游数据工程的职责——把重复语料喂进来，产物里就会有
> 重复内容，且会在跨 epoch 训练中被重复消费。

> **小语料的 shard 数提醒**：`batches_per_shard=0`（自动）按 ~128MB/shard 聚合，小数据集可能
> 只产出 1 个 shard；而加载端强校验 `shard 数 >= world_size`（杜绝大集群 rank 空转）。
> 分布式训练小数据集时，请把 `batches_per_shard` 调小（甚至 1），让 shard 数 ≥ world_size。
> 构建端也会在 **shard 数 < 8**（常见 DDP 规模）时直接 WARN 提示（`Dataset has only N shard(s) (< 8)`），
> 把这一错配提前到构建期暴露，而不用等到训练启动才报错。

### 2.2 构建 SFT（对话微调）数据集

SFT 需要一份 **Jinja2 模板**（minijinja 渲染），模板里可访问 `messages` / `conversations` /
`tools` / `add_generation_prompt`。**模板变量与数据 key 的对应关系**（对应错了会被静默过滤，
0 产出时构建直接报错，见下）：

- `messages` 模板变量**兼容两种数据**：数据里是 `messages` 或 `conversations` 都会映射给它；
- `conversations` 模板变量**只认**数据里的 `conversations` key——`messages` 数据配
  `conversations` 模板会渲染失败，所有行被过滤，构建以 "Build produced 0 shards" 报错；
- 渲染失败/非法 JSON 的脏行会在收尾汇总 WARN（`N/M input rows were discarded`），构建继续；
- **模板空白行为**：渲染引擎固定开启 `trim_blocks` 与 `lstrip_blocks`——Jinja2 块标签
  （`{% for %}` / `{% endfor %}` 等）独占的行不会产生多余换行，`{{ ... }}` 前的行首缩进被剥除。
  写模板时**不要依赖块标签产生的空白**；需要显式空白请用 `{{ " " }}` 或把标记与内容写在同一行。

```python
from megadata.builder import BuildConfig, Marker

TEMPLATE = "{% for m in conversations %}<|im_start|>{{ m.role }}\n{{ m.content }}<|im_end|>\n{% endfor %}"

builder.build_dataset(BuildConfig(
    input_paths=["data/sft_t2t_mini.jsonl"],
    output_dir="out/sft",
    mode="sft",                       # 默认值就是 "sft"
    template_str=TEMPLATE,
    batch_size=BATCH_SIZE,
    turn_start=Marker(text="<|im_start|>"),   # 掩码状态机靠这两个特殊符分段
    turn_end=Marker(text="<|im_end|>"),       # （SFT 下不传 eos，传了会报错）
    assistant_str="assistant",         # 只有该角色的回复计入 loss
    batches_per_shard=16,
))
```

其它常见模板（换 tokenizer 时同步换字符串即可）：

| 模型族 | `turn_start` | `turn_end` | `assistant_str` |
|---|---|---|---|
| Qwen / ChatML | `<\|im_start\|>` | `<\|im_end\|>` | `assistant` |
| Llama-3 | `<\|start_header_id\|>` | `<\|eot_id\|>` | `assistant` |
| Gemma | `<start_of_turn>` | `<end_of_turn>` | `model` |

**SFT 掩码语义**（`src/packing/document_aware.rs::generate_labels`）：

- 状态机按 `turn_start_str/id`、`turn_end_str/id` 分段，`assistant_str` 之后的段标记为"监督位"；
- 监督位取 **next-token**：`labels[t] = input_ids[t+1]`；段末与所有非监督位是 `-100`；
- 多个对话样本装箱进同一行（`max_seq_len` 内），行尾 padding 的 label 也是 `-100`；
- **超长截断（tail 策略）**：单篇对话超过 `max_seq_len` 时尾部直接丢弃，**构建期会统计并在
  收尾 WARN**（含比例与丢弃 token 数），同时写入 `index.json` 的
  `global_stats.truncated_docs` / `truncated_tokens`（为 0 时省略该字段）——如果 user 段本身
  占满 `max_seq_len`，assistant 段会被整段截掉，产出 `labels` 全 `-100` 的"废样本"（计入
  进度快照的 `all_masked_docs`）。务必检查这两个计数是否为 0；
- **分隔符注入风险（F7）**：掩码靠 turn 标记字符串/单 token 识别轮次——若 user 内容里嵌入了
  `<|im_start|>assistant` 这类标记文本，会被状态机当成真实轮次监督（监督泄漏）。构建期会做
  **注入检测**（token 流中轮次标记数 ≠ 源数据轮次数 → 进度快照 `docs_flagged_injection` 计数
  + 限频 WARN，**不丢样本**）；计数 > 0 时请清洗数据或在模板/分词器层转义。

### 2.3 读取并训练

```python
from megadata import BatchStream

loader = BatchStream(
    "out/pt/index.json", batch_size=BATCH_SIZE, max_seq_len=MAX_SEQ_LEN,
    world_size=1, rank=0, seed=42,
)

for step, batch in enumerate(loader):
    ids = batch["input_ids"]              # (B, S) int32，DLPack 零拷贝到 CPU 张量
    cu  = batch.get("cu_seqlens")         # list[int]，batch 级文档边界（varlen 用）
    ...
```

SFT 的 batch 多两列：

```python
batch = next(iter(BatchStream("out/sft/index.json", batch_size=BATCH_SIZE, max_seq_len=MAX_SEQ_LEN,
                                       world_size=1, rank=0)))
batch.keys()      # input_ids / labels / position_ids / cu_seqlens（+ row_lens）
loss = model(input_ids=batch["input_ids"], labels=batch["labels"], ...)
```

> **`row_lens`**（每行有效长度，不含行内 padding）：新构建的 SFT 数据集携带该列
> （A4 数据自描述，构建期写入 Arrow）；旧数据集没有该键，读取端回退到复刻装箱
> 算法。它让 SFT 也能走 varlen 连续流（见 §4.6）。

把 `cu_seqlens` 接到 FlashAttention varlen（细节见 §4.6）：

```python
from megadata import flatten_and_unpad, to_flash_varlen
fmt = batch.get("format")                             # "pt" / "sft"
ids_1d = flatten_and_unpad(batch["input_ids"], batch["cu_seqlens"],
                           packer=fmt, row_lens=batch.get("row_lens"))   # (valid_len,)
cu_qk, max_s = to_flash_varlen(batch["cu_seqlens"])
```

## 三、构建期：`DataBuilder` 详解

### 3.1 输入数据格式

| 模式 | 每行 JSON | 备注 |
|---|---|---|
| `mode="pt"` | `{"text": "..."}` | 文本被 tokenize 后按 Greedy Packing 拼成一维流（文档可跨行拼接） |
| `mode="sft"` | `{"conversations": [{"role","content"}, ...]}` 或 `{"messages": [...]}` | 经 `template_str` 渲染成一条完整对话串再编码；`tools` 字段也会透传给模板 |

### 3.2 完整参数表（推荐 `BuildConfig` 值对象）

```python
from megadata import DataBuilder
from megadata.builder import BuildConfig, Marker

cfg = BuildConfig(
    input_paths=["raw.jsonl"],
    output_dir="out/sft",
    mode="sft",                # "pt" | "sft"（拼错在构造期报错）
    template_str="...",        # SFT 必填（Jinja2/minijinja 模板）
    batch_size=16,             # ★ 烧入 shard：加载期必须一致，否则报错
    pad_id=0,
    eos=Marker(),              # PT 专属（未设置 = 用默认 "<|endoftext|>" 自动推导）
    turn_start=Marker(),       # SFT 专属（默认 "<|im_start|>"，强校验恰好 1 token）
    turn_end=Marker(),
    assistant_str="assistant",
    batches_per_shard=0,       # 0 = 自动（约 128MB/shard）
    compression="auto",        # "auto" | "zstd" | "lz4" | "none"
    extra_columns=False,       # 文档级旁路列 doc_ids / loss_weights（见 §3.6）
)
DataBuilder(tokenizer_path, max_seq_len=8192).build_dataset(cfg, progress_cb=None, ...)
```

- **`progress_cb` 不属于 `BuildConfig`**：划分标准是"配置 = 决定产物 / 进 manifest 指纹；
  回调 = 运行期副作用"，所以它留在 `build_dataset` 签名里（见 §3.3）；
- **模式相关性在构造期强校验**：`mode="sft"` 传 `eos=`、`mode="pt"` 传 `turn_start=`/`turn_end=`
  直接 `ValueError`（**传了也不会生效——响亮失败优于静默忽略**）；
- **`Marker(text=None, id=None, strict=True)`**：`id` 未设时自动从 `text` 推导（默认文本内建）；
  `strict=True`（turn 默认）要求编码恰好 1 个 token 否则报错；`strict=False`（eos 默认）
  非单 token 时告警取首个（eos 只影响文档边界，turn 会损坏监督标签——分级是有意的）；
- 新旧写法混用（同时给 `eos=` 与 `eos_str=`/`eos_id=`）直接报错，不静默取舍。

### 3.6 文档级旁路列：`doc_ids` / `loss_weights`（PT 数据集）

需要**文档级**信息（逐 token 的文档归属、逐 token loss 权重）时开启 `extra_columns=True`：

```python
cfg = BuildConfig(input_paths=["raw.jsonl"], output_dir="out/pt", mode="pt",
                  batch_size=16, extra_columns=True)
DataBuilder(tokenizer_path, max_seq_len=8192).build_dataset(cfg)

# 加载期：batch 多出两个零拷贝张量
for batch in BatchStream(index_json_path="out/pt/index.json", batch_size=16, max_seq_len=8192):
    doc_ids = batch["doc_ids"]        # int32, (B, S)；padding 位置 = -1
    weights = batch["loss_weights"]   # float16, (B, S)；padding 位置 = 0.0，其余默认 1.0
```

- **用途**：`doc_ids` 供文档级 loss 加权 / 课程学习 / 训练样本追溯（`cu_seqlens` 只给边界不给身份）；
  `loss_weights` 可直接乘进 per-token loss。
- **代价**：每 shard 多两个定宽文件（`.col_doc_ids` 4 字节/token、`.col_loss_weights` 2 字节/token），
  约 +1.5× token 字节量；**默认关闭**，不开启时零额外开销。
- **兼容性**：仅 PT/Memmap 数据集支持（SFT/Arrow 不写该列）；旧数据集没有这两个 key，
  batch 里也就不会出现这两个键（读取端按 manifest schema 判定，不报错）。
- **校验**：`python -m megadata.validate <index.json> --deep` 会校验列文件存在性与定宽。

旧扁平签名（兼容期，会发 `DeprecationWarning`，后续版本移除）：

```python
DataBuilder(tokenizer_path, max_seq_len=8192).build_dataset(
    input_paths, output_dir,
    mode="sft", template_str="...", batch_size=16, pad_id=0,
    eos_id=None, turn_start_id=None, turn_end_id=None,       # eos 为 PT 专属
    eos_str="<|endoftext|>", turn_start_str="<|im_start|>", turn_end_str="<|im_end|>",
    assistant_str="assistant", batches_per_shard=0, compression="auto",
    progress_cb=None,
)
```

关键参数说明：

- **`batch_size` / `max_seq_len`**：不是"建议"而是**硬契约**。数据在构建期已按 `batch_size × max_seq_len`
  预打包，加载期两者必须一致（`index.json` 记录了 `global_stats.batch_size`，加载端不一致直接报错）。
- **token ID 自动推导**：`Marker.id` 未显式传入时，用当前生效分词器编码 `Marker.text` 得到
  （显式传参优先）。`bbpe_tokenizer` 不可用且未显式传参会抛 `ValueError`。
  **换 tokenizer 时请确认这些特殊符存在且为单 token**。
- **`batches_per_shard`（shard 聚合）**：把 N 个 batch 打进一个 shard 文件，文件数从"每 batch 一个"
  降到几百个，解锁云 IO 批量与压缩。约束：**shard 数 ≥ world_size**（加载端强校验，否则高位 rank 无数据）；
  `shard 数 < world_size × num_workers` 时只告警（部分 worker 空转）。
  经验：`batches_per_shard ≈ 总 batch 数 / (world_size × 5~20)`。
- **`compression`（`"auto" | "zstd" | "lz4" | "none"`）**：
  - `"auto"`（默认）：PT → per-batch zstd frame（`Zstd-MDS`，保留 O(1) 随机寻址）；
    SFT → 不压缩（Arrow IPC 原生压缩需显式指定）；
  - `"zstd"` / `"lz4"`：显式算法（SFT 走 Arrow IPC 原生压缩，读取端透明）；
  - `"none"`：显式关闭。
  - ⚠️ `None` **不再是合法值**（v1/v2 里 `None` 与 `"none"` 的视觉陷阱已消灭）：传 `None` 报 `ValueError`。
  - PT 压缩实测（真实语料）：压到 42.2%、解压 629MB/s、随机访问 +103µs/batch
    （依据见 `bench/compression_bench.py` 与实现说明第六节）。
- **`template_str` 不能为空**：SFT 下空模板会渲染成空文本，构建出 `0 shard / 0 token` 的废数据集
  （加载时才报错）。`BuildConfig` 构造期即发 `UserWarning` 提醒。

### 3.3 进度与取消

```python
builder.get_progress()   # dict: bytes_read/docs_read/docs_tokenized/shards_written/bytes_written/
                         #      docs_truncated/tokens_dropped_to_truncation/all_masked_docs(SFT 截断统计)、
                         #      docs_flagged_injection(疑似 turn 标记注入)/elapsed_secs
builder.cancel()         # 请求取消（构建线程会在下一个检查点退出）
# 或 build_dataset(..., progress_cb=lambda p: ...)  每 ~100ms 回调一次
```

取消或失败时**不会留下半成品**：`build_dataset` 抛异常（取消抛 `KeyboardInterrupt`），
本次已写出的 shard（含 `.cu`/`.idx`）会被清理，`index.json` 不会落盘。
因此 **"目录里有 `index.json`" 就是"构建完整"** —— 可以据此安全地判断是否需要重建：

```python
import os
if not os.path.exists(os.path.join(out_dir, "index.json")):
    builder.build_dataset([...], out_dir, ...)   # 上次没跑完，重来
```

**读源错误一定会报错**（不再静默产出部分数据集）：输入文件不存在、读到中途出错（如非法
UTF-8）都会抛 `OSError`，消息带出错的路径。

### 3.4 产物结构与校验

```jsonc
{
  "version": "2.0",             // 加载端校验（支持 "1.0"/"2.0"）
  "format": "Zstd-MDS",         // Memmap | Zstd-MDS | Arrow-IPC
  "max_seq_len": 256,
  "global_stats": {
    "total_tokens": 123456,     // 真实有效 token（不含 padding）
    "batch_size": 8,            // 加载端一致性校验用
    "truncated_docs": 0,        // SFT 截断审计（超长 tail 截断的文档数 / 丢弃 token 数）；
    "truncated_tokens": 0       // 为 0 时这两个字段整体省略（旧格式兼容）
  },
  "shards": [{
    "shard_id": 0,
    "filename": "shard_00000.bin",
    "num_batches": 16,
    "size_bytes": 1048576,
    "hashes": {"sha256": "…64hex…",      // 构建期写完回读记账；云端下载后强制校验；
                "sha256:cu": "…", "sha256:idx": "…"}   // 本地默认不校验（零开销），
  }]                                      // 可用 MEGADATA_VERIFY_LOCAL=1 开启全量、
}                                         // =sample:P 按比例抽样（见 §8 / 控制面说明）
```

配套文件：`shard_XXXXX.cu`（每 batch 的 cu_seqlens，PT 用；旧数据集缺失时退回标准 attention
语义，manifest 记了 hash 却取不到合格文件则会报错）、`shard_XXXXX.idx`（Zstd-MDS 的压缩字节
偏移表，缺失/损坏会明确报错）。构建统计与 shard 列表做交叉校验（`total_batches == Σ
num_batches`），被截断/手改的 `index.json` 会在加载期被拒。

`index.json` 另有可选的 `tokenizer` 块（v3.1 起），**只写不读**，用于追溯"这份数据集是用
哪个分词器构建的"：

```jsonc
"tokenizer": {
  "backend": "bbpe",              // "bbpe"（Rust 直连）| "python"（第三方分词器）
  "identity": "3f9c…@v1",         // bbpe: sha256(文件)[:16] + format_version；python: name_or_path
  "vocab_size": 151936            // 不可得时省略
}
```

它不是数据集身份（那是 `manifest_fingerprint`），读取端不做任何校验——防呆靠构建工具：换
分词器重建后这个值会变，一眼可辨。

### 3.5 第三方分词器接入（HF / tiktoken / 自研）

bbpe_rs 之外的分词器都能接进来，**只有"把文本变成 id"这一步换成 Python**，渲染、装箱、
压缩、写盘、索引仍在 Rust：

```python
from megadata import DataBuilder, HfTokenizerAdapter

# ① HF 分词器文件（tokenizer.json 或所在目录）—— 与 tokenizer_path= 完全等价
adapter = HfTokenizerAdapter.from_file("/path/to/tokenizer.json")

# ② 完整 HF 体验（trust_remote_code / chat template 等）
adapter = HfTokenizerAdapter.from_pretrained("Qwen/Qwen2.5-7B", trust_remote_code=True)

# ③ 其实 tokenizer_path 指到非 bbpe 的 tokenizer.json 时会自动走这条路
builder = DataBuilder(tokenizer=adapter, max_seq_len=4096)
builder.build_dataset([...], out_dir, mode="sft", template_str=chatml, batch_size=8)
```

自研 / tiktoken / vLLM 分词器：实现两个方法即可（鸭子类型，无需继承）：

```python
class MyTokenizer:
    def encode_sft_batch(self, texts):        # SFT：标记字符串识别为单 token
        return ids_batch, tokens_batch        # 两个 list 等长，与 texts 等长
    def encode_ordinary_batch(self, texts):   # PT：标记字符串按普通文本切碎
        return ids_batch
```

契约要点：ids 必须非负且 ≤ 2^31-1；空文本返回空 list 合法；`add_special_tokens` **恒为
False**（构建期注入 BOS/EOS 会让所有文档长度错位）。返回值格式/长度错误、非法 id 都会在
构建期报错，不会静默写坏数据。

**构建期强校验（D8）**：`turn_start_str` / `turn_end_str` 经当前生效分词器编码必须**恰好
1 个 token**；显式传入 `turn_start_id` / `turn_end_id` 时还必须一致。违反直接报错——多 token
会导致 assistant 段识别错误、监督标签静默损坏，宁可构建失败。

## 四、加载期：加载器详解

### 4.1 选型

```
已构建好数据集，需要读取？
├─ 需要按 idx 随机访问（评估/调试/抽查）      → RandomAccessBatchReader（勿再套 torch DataLoader）
├─ 训练主力（推荐）                            → BatchStream
│   ├─ 打乱（默认）                             → shuffle="permutation"
│   ├─ 关闭 batch 级置换（调试）                  → shuffle="none"
│   └─ 全局逐 shard 顺序扫描（逐 token 核对语料）  → shuffle="none" + shard_order="sequential"
├─ 多源配比 / 课程学习 / 退火                  → MixBatchStream
└─ HF Trainer / Lightning 直接接管             → StreamingDataset + MegadataDataLoader
```

### 4.2 公共参数（五入口共用）

| 参数 | 默认 | 说明 |
|---|---|---|
| `index_json_path` | — | `index.json` 路径，支持本地 / `http(s)://` / `s3://` / `gs://` |
| `batch_size` | `None`（→ manifest） | 必须与构建期一致（否则报错） |
| `max_seq_len` | `None`（→ manifest） | 同上 |
| `world_size` / `rank` | `None` | `None` 时依次从 `torch.distributed`、`WORLD_SIZE`/`RANK` 环境变量回退（**回退时告警一次**；`MEGADATA_STRICT_TOPOLOGY=1` 禁止回退） |
| `seed` | `42` | 决定 shard 打乱与置换表；**续训必须与原始 run 相同** |
| `shuffle` | `"permutation"` | `"permutation"`（置换表打乱）/ `"none"`（关闭 batch 级置换；**shard 访问顺序仍由 `(seed, epoch)` 决定**，并非全局逐 shard 顺序扫描）；布尔 `True`/`False` 为等价简写；`"buffer"` 已在 v3 移除。**`RandomAccessBatchReader` 无此参数**（见下"公共参数集与差异"） |
| `partition` | `"round_robin"` | `"round_robin"`（默认）或 `"relaxed"`（弹性扩缩容，见 §4.4） |
| `shard_order` | `"random"` | epoch 内**全局 shard 访问顺序**：`"random"`（默认，按 `(seed, epoch)` 打散，历史行为）或 `"sequential"`（不打散，RoundRobin 下全局序恒为 `0..n`、跨 epoch 稳定；Relaxed 下为 canonical 块内按序）。与 `shuffle` **正交**：本参数决定"哪些 shard 以什么顺序被访问"，`shuffle` 决定"shard 内部的 batch 顺序"——严格顺序扫描用 `shuffle="none" + shard_order="sequential"`。**`RandomAccessBatchReader` 无此参数**。改它不会改变各 worker 的 shard **集合划分**，只改变访问顺序（划分仍由 `(seed, epoch, 拓扑)` 决定） |
| `num_canonical_nodes` | `None` | 仅 `relaxed` 用；**续训时须显式与首个 run 保持一致**（当前不会从快照自动恢复该值） |
| `predownload` | `None`（→ Rust 默认 **16**） | 预取在途 batch 上界；`<4` 会告警（预取窗口太小掩不住 IO 延迟） |
| `epoch` | `0` | 起始轮号；`load_state_dict` 会用快照值覆盖（P5/C27） |

> `num_workers` / `worker_id` **不是**引擎层参数：多 worker 一律走
> `StreamingDataset` + `MegadataDataLoader`（§4.8），worker 维度在 worker 进程内自动探测。

`len(loader)` = **该轮将产出的 batch 数**（"下一次迭代实际会产出多少"口径）：
`load_state_dict` 恢复后为 `轮长 − 恢复位置`（与 `MixBatchStream` 确定性模式同口径，
HF 侧按 `len()` 排的 LR scheduler 与真实步数对齐）；恢复位置被消费后回到整轮长。
一次 `for` = 恰好一个 epoch（`num_epochs` 已在 v3 移除，轮数归训练脚本）。

**轮号协议（两层统一）**：`epoch` 属性 = "下一次 `__iter__` 将产出的轮"；
手动设置用 `set_epoch(k)`（引擎层与 Tier-1 都提供；活跃迭代会话中调用抛 `RuntimeError`
——生效时序未定义）。`MixBatchStream.set_epoch` 会重建 mixer（Rust 的 `start_epoch` 是构造期落点）。
`BatchStream` 的 `len()` 走**纯函数查询**（不构造读头、不启动预取线程）。

> **跨 epoch 必然重复（设计语义）**：多 epoch 训练 = 同一份数据按新的 `(seed, epoch)` 重新
> 打乱后再消费一遍——engine 不做"跨 epoch 不重复采样"。单 epoch 内无重复；相邻 epoch 间
> 每条数据都会再次出现（顺序不同）。需要"每条数据只训一遍"的语料级调度，请在训练脚本层
> 控制总轮数或自己管理数据版本。

**参数收敛（`LoaderOptions`，推荐写法）**：`options=` 是五个入口统一推荐的传参方式——
一份加载参数可复用于多个 loader（train/val 同参），`shuffle` / `partition` 的归一化与
合法性校验只在构造期发生一次（拼错构造期即报错）：

```python
from megadata import LoaderOptions, BatchStream

opts = LoaderOptions(batch_size=8, max_seq_len=4096, world_size=64, rank=rank, seed=1024)
train_loader = BatchStream("out/train/index.json", options=opts)
val_loader   = BatchStream("out/val/index.json", options=opts)
```

- **扁平参数写法完全等价保留**（本文其余示例即扁平写法），不设 deprecation；
  `options=` 与扁平参数**互斥**：同时传入且值偏离默认 → `ValueError`（配置来源必须唯一）；
- `batch_size` / `max_seq_len` / `predownload` 传 `0` 或 `None` 均表示"取默认 / manifest 值"
  （与扁平签名一致），负数报错；
- 五个入口（`BatchStream` / `MixBatchStream` / `RandomAccessBatchReader` /
  `StreamingDataset` / `MixStreamingDataset`）都支持 `options=`；
- **公共参数集与差异**：上表参数在五个入口同名同义；差异仅两处——
  ① `RandomAccessBatchReader` **无 `shuffle`**（无置换表语义，按 idx 直取没有"顺序"可打乱；
  经 `options=` 传入的 `shuffle` 照单接收但**有意忽略**，需要打乱请用 §4.3 / §4.7）；
  ② `Mix*` 两入口额外有 `weights` / `steps_per_epoch`（仅 `MixBatchStream` 消费，Tier-1 透传）。

### 4.3 `BatchStream`

```python
BatchStream(index_json_path, *, batch_size=None, max_seq_len=None, world_size=None, rank=None,
             seed=42, shuffle="permutation", partition="round_robin", shard_order="random",
             num_canonical_nodes=None, predownload=None, epoch=0)
```

> 除 `index_json_path` 外全部为 keyword-only，且 `batch_size` / `max_seq_len`
> 未传时从 manifest 读取（构建期已记录）。

- `shuffle="permutation"`（**默认，推荐**）：Rust 侧按 `(seed, epoch)` 生成 batch 级**确定性置换表**，
  无有状态 buffer，`state_dict` 只有几十字节，恢复 = 一次 seek；
- `shuffle="none"`：**只关闭 batch 级置换**（batch 按 shard 内顺序产出）；shard 访问顺序仍由
  `(seed, epoch)` 决定（除非同时设 `shard_order="sequential"`，见下），因此不是
  "全局逐 shard 顺序扫描/全局复现"语义。布尔写法 `True` / `False` 是等价简写；
- `shard_order="sequential"`：epoch 内全局 shard 序不打散（RoundRobin 下恒为 `0..n`，跨 epoch
  稳定）。与 `shuffle` 正交——**逐 token 核对语料、与离线工具对齐顺序**的用法请组合
  `shuffle="none" + shard_order="sequential"`；多 worker 时仍按扁平编号取模互斥划分
  （worker w 拿序位 w, w+T, w+2T…）；
- `shuffle="buffer"` 已在 v3 **移除**（permutation 是其超集），传入会 `ValueError`。

### 4.4 分布式与弹性扩缩容

- **DDP**：把 `world_size`/`rank` 交给 megadata，**不要再套 `torch.utils.data.DistributedSampler`**
  （会双重切分）。
- **worker 维度**：`num_workers>0` 时每个 `(rank, worker)` 拿到**互斥**的 shard 子集，
  reader 在 worker 进程内惰性构造（fork 安全）。**注意：改 `num_workers` 会改变 rank 级
  shard 划分本身**（不只是切分方式）——`num_workers=1→2` 后 rank 看到的 shard 集合不同
  （大小不变、DDP 并集仍完整）；**复现/续训必须固定 `num_workers`**（续训时快照拓扑
  变化会告警，见 `_warn_if_topology_changed`）。
- **弹性扩缩容（`partition="relaxed"`）**：全局 epoch 序只依赖 `(seed, epoch, num_canonical_nodes)`，
  与当前拓扑无关；节点数变化后仍可按快照的 `(epoch, in_epoch_pos)` 精确续训。
  续训时请**显式保持 `num_canonical_nodes` 与首个 run 一致**（当前实现不会从快照自动恢复该值）。

```python
loader = BatchStream(
    "out/pt/index.json", batch_size=BATCH_SIZE, max_seq_len=MAX_SEQ_LEN,
    world_size=64, rank=int(os.environ["RANK"]),
    partition="relaxed", num_canonical_nodes=32,   # 锚点（= 首个 run 的节点数）
)
```

### 4.5 batch 结构

| 模式 | keys | 类型 |
|---|---|---|
| PT（Memmap / Zstd-MDS） | `input_ids`、`cu_seqlens`、`format` | `input_ids`: `(B, S)` int32 tensor（DLPack 零拷贝）；`cu_seqlens`: **int32 tensor**（v3 起张量化），长度 = 文档数+1，覆盖整个 batch 的一维流（文档跨行拼接，padding 集中在流末尾）；`format="pt"` |

> ⚠️ **PT 长文档会被跨 batch 切分（重要）**
>
> PT 模式**不截断**超长文档，但长度超过 `batch_size × max_seq_len` 的文档会被**连续铺到多个
> batch**，每段在 `cu_seqlens` 里各自成为一个独立段。此时若训练侧按上表用 FlashAttention
> **varlen**（推荐做法），**每段都是 position 从 0 开始的独立序列，跨 batch 的文档上下文会被
> 静默切断**——数据一个字节没丢，但语义已经变了。
>
> 本项目现已把这件事**变成可见的**：构建期统计切分文档数/ token 数，汇总 WARN，并写入
> `index.json` 的 `global_stats.split_docs` / `split_tokens`；加载该数据集时会再 WARN 一次。
>
> **应对**：把 `max_seq_len` 设到「覆盖绝大多数文档的长度」（先看构建 WARN 里的占比与平均
> token 数），使长文档落进单个 batch。若构建时开了 `extra_columns=True`，也可以事后用
> `doc_ids` 旁路列检出同一 uid 出现在多个 batch 的情况。
| SFT（Arrow-IPC） | `input_ids`、`labels`、`position_ids`、`cu_seqlens`、`row_lens`、`format` | 均为 tensor；`labels` 非监督位为 `-100`；`cu_seqlens` 是**逻辑偏移**（文档不跨行、padding 分散在每行末尾）；`row_lens` 为**每行有效长度**（新构建数据集自带；旧数据集无该键，读取端回退复刻装箱）；`format="sft"` |

> F-10：单源 / 同构多源 / 异构混采三种路径的 batch **都**携带 `format` 键——
> `mask_adapter` 建议的 `packer=batch.get("format")` 防护因此在全部路径生效
> （此前只有异构混采才带，单源路径防护永不生效）。

### 4.6 `cu_seqlens` 与 attention 后端（`megadata.mask_adapter`）

| 函数 | 作用 |
|---|---|
| `normalize_cu_seqlens(cu)` | 归一为 int64 tensor（list/tensor 均可） |
| `valid_len(cu, total_len=None)` | 有效 token 数（`cu[-1]`） |
| `cu_seqlens_to_seg_lens(cu)` / `cu_seqlens_to_doc_ids(cu, total_len)` | 分段长度 / 逐 token 文档 id |
| `sft_row_lens(cu, B, S, *, row_lens=None, labels=None)` | SFT 每行有效长度：`row_lens` 列直读或复刻装箱；`labels` 给出时校验行尾不变式 |
| `flatten_and_unpad(t, cu, total_len=None, packer=None, *, row_lens=None)` | `(B,S,…)` → `(valid_len,…)`；`packer="sft"` 按行有效长度抽取，`"pt"`/`None` 取前 valid_len 个 |
| `repad_to_batch(t1d, cu, B, S, pad_value=0.0, packer=None, *, row_lens=None)` | `(valid_len,…)` → `(B,S,…)`；**布局必须与 flatten 对称**（SFT flatten 配 SFT repad） |
| `to_flash_varlen(cu, total_len=None)` | → `(cu_seqlens_int32, max_seqlen)`，直接喂 `flash_attn_varlen_func` |
| `to_flex_block_mask(cu, total_len=None, causal=True, block_size=128, device=None, compile_mask=True)` | → FlexAttention `BlockMask`（PyTorch ≥2.5） |
| `to_xformers_block_diag(cu, total_len=None, causal=True)` | → xformers `BlockDiagonalCausalMask` |
| `build_attention(cu, backend, total_len=None, causal=True, **kwargs)` | 按 `"flash_varlen"`/`"flex"`/`"xformers"` 分发；`AttentionBackend` 枚举等价。**`flash_varlen` 仅支持 `causal=True`**（其返回物不含因果信息），传 `causal=False` 抛 `ValueError`；双向请用 `flex`/`xformers` |

调用依赖按需导入：`build_attention(..., "flash_varlen")` 需要 `flash_attn`（**门面处**校验；
`to_flash_varlen` 本体是纯转换、不要求安装——只想拿 `(int32 cu, max_seqlen)` 喂自研 kernel
的场景可直接用），`flex` 需要 torch≥2.5 的 FlexAttention，`xformers` 需要 xformers ——
未安装时相关入口会抛带安装提示的错误，**不影响 PT/SFT 的纯数据路径**。

> **PT 与 SFT 的 flatten 布局不同，用 `packer=` 选择（传 `batch.get("format")` 自动）**：
> PT 的文档跨行连续拼接，`flat[:valid_len]` 就是连续文档流；
> SFT 的 padding 分散在每行末尾、`cu_seqlens` 是逻辑偏移，`packer="sft"` 会按
> `row_lens`（新数据集列直读；旧数据集回退复刻装箱算法）逐行切片，得到与
> `cu_seqlens` 一一对应的连续流，直接接 varlen / Flex：
>
> ```python
> fmt = batch.get("format")
> ids_1d = flatten_and_unpad(batch["input_ids"], cu, packer=fmt, row_lens=batch.get("row_lens"))
> block_mask = to_flex_block_mask(cu, causal=True)
> logits = repad_to_batch(model(ids_1d), cu, B, S, packer=fmt, row_lens=batch.get("row_lens"))
> loss = loss_fn(logits, batch["labels"])      # 布局对称，行内 labels 不会错位
> ```

### 4.7 `MixBatchStream`（多源配比 / 课程学习）

```python
MixBatchStream(datasets_config, *, weights=None, steps_per_epoch=None,
          batch_size=None, max_seq_len=None, world_size=None, rank=None, seed=42,
          shuffle="permutation", partition="round_robin",
          num_canonical_nodes=None, predownload=None, epoch=0)

# datasets_config: [{"path": ".../index.json", "weight": 0.7}, {"path": "...", "weight": 0.3}]
```

> 除 `datasets_config` 外全部为 keyword-only；`weight` 也可以走 `datasets_config` 内的
> `"weight"` 键（两种来源互斥，混合指定会报错）。

- 省略 `weight` 时按各数据集 `global_stats.total_tokens` 自动配比（`w_i ∝ tokens_i`）；
  manifest 读取走 Rust（本地 / `http(s)` / `s3` 都可，带重试退避），
  也可以用 `megadata.read_manifest(path)` 自己看；
- **weight 必须全部指定或全部省略**（混用会抛 `ValueError`：配比语义不明确）；全部为 0 也报错；
  省略 weight 时若有数据集 `total_tokens == 0`（空数据集/构建失败）会抛 `ValueError`；
- **权重两层模型（意图与生效分离）**：
  - `update_weights([...])`：设定**基础权重**（用户显式接管，同时清除温度），**相对权重**口径，
    长度必须等于子流数；
  - `update_temperature(T)`：在**基础权重**上应用温度算子（`w_i ∝ base_i ** (1/T)`）——
    显式权重（构造 `weights=` / configs 的 `weight`）**不会**被静默重置为 token 配比；
    重复调用**幂等**（T=2 后再 T=4 等价于直接 T=4，不复合）；`T <= 0` 报 `ValueError`；
  - `state_dict()` 同时记录 `base_weights` 与 `temperature`（旧快照自动按 `weights` 当 base 兜底），
    续训后退火口径不漂移；
  - 非法权重（长度错 / NaN / 负数 / 全零）统一抛 `ValueError` 且**不改动内部状态**（失败原子性）；
- 注意 **异构 schema**：PT 批次有 `input_ids/cu_seqlens`，SFT 批次有 `labels/position_ids`；
  训练循环需按 `"labels" in batch` 分支。**所有 batch 都携带 `format` 键**（`"pt"`/`"sft"`），
  也可用它分派（`if batch["format"] == "sft": ...`）。
- **轮长与续训**：`steps_per_epoch=N`（确定性模式）下，`len(loader)` 是**本轮剩余步数**；
  在 k 步处断点续训后，本次迭代只产出 `N−k` 步（轮边界不会被拉长，LR scheduler 按 `len()`
  排程始终对齐）。自然模式（`steps_per_epoch=None`）在于流耗尽时结束，`len()` 是上界。
- **`shuffle` 的口径**：`shuffle` 控制**子流内**的 batch 级置换表（与其他两个入口接受同一
  取值集合）。子流之间的顺序由 mixer 的**加权随机采样**决定、**不可关闭**（`seed` 固定则可
  复现）——因此 `shuffle="none"` 的承诺是"子流内顺序读取"，而不是"整个 MixBatchStream 纯顺序"。
  shard 级归属始终逐轮轮换（尾 shard 均衡）；`partition="relaxed"` 的"全局序与拓扑无关"
  是 **shard 级**，batch 级全局序仍依赖拓扑与采样。
- **自然模式 + DDP（`steps_per_epoch=None` 且 `world_size>1`）**：各 rank 的轮长必须恒等，
  否则轮末训练循环的集合通信会 hang。构造期只做**无集合通信**的本地静态判定（用 manifest
  即可判）：等长 shard 且按 (rank, worker) 均衡分配 → 可证明安全；等长 shard 但分配不均 →
  直接 `RuntimeError`；shard 尺寸不齐 → 无法静态证明，**告警一次**。需要确凿结论时，在训练
  循环开始前（所有 rank 的同一同步点）显式调用 `loader.verify_ddp_consistency()` /
  `ds.verify_ddp_consistency()`——这是一次 `all_gather`，**所有 rank 必须对称调用，且禁止在
  DataLoader worker 内调用**。`MEGADATA_SKIP_DDP_CHECK=1` 关闭以上全部检查。
  **推荐做法仍是显式传 `steps_per_epoch`（确定性模式天然同步）。**
  **检测面边界**：构造期的本地判定只读本 rank 的 manifest，证明"轮长恒等"；**不覆盖各
  rank manifest 内容漂移**（各 rank 的 `index.json` 不同但各自自洽时仍可能通过）。该场景
  请在训练循环同步点显式 `verify_ddp_consistency()`（`all_gather` 逐子流轮长向量，可发现
  rank 间差异）。

### 4.8 HF / Lightning 集成

```python
from megadata import StreamingDataset, MegadataDataLoader

ds = StreamingDataset("out/sft/index.json", batch_size=8, max_seq_len=256,
                      shuffle="permutation")
dl = MegadataDataLoader(ds, num_workers=2)      # batch_size=None + identity collate
trainer.fit(model, train_dataloaders=dl)

dl.state_dict()      # {"num_batches_yielded", "dataset", "tier1", "resume_granularity"}
dl.load_state_dict(state)
```

- `num_workers>0` 可用（`__iter__` 在 worker 内惰性构造 reader，每个 worker 拿互斥 shard 子集）；
  但此时**主进程拿不到 dataset 进度**（reader 活在 worker 进程里）→ `state_dict()["dataset"] == {}`，
  快照的 `resume_granularity` 会自述精度（`"epoch"`）；`load_state_dict` 在**确已产出批次**时
  明确告警（对"刚构造就 save"不误报——论据诚实）。需要**批级精确续训**请用 `num_workers=0`——
  此时 `resume_granularity == "batch"`，`state_dict()` 含 `epoch / in_epoch_pos`，恢复后从原位置继续读；
- **`len(dl)` 可用**（`StreamingDataset.__len__` 走纯函数查询，不构造读头）：
  返回本 rank 当前轮的 batch 数（恢复待消费时是"剩余步数"；`num_workers>0` 时**不除** worker 数——
  主进程拿到的就是本 rank 整轮步数，正是 LR scheduler 要的数）。按 `len()` 排 schedule 的框架可直接用，
  配 `per_device_train_batch_size=1`、关闭框架自身 sampler/shuffle；
- 轮号推进：`MegadataDataLoader.__iter__` 结束时自动推进（**persistent worker** 由 worker 进程内
  自推进，按构造参数显式分派）；手动推进用 `ds.set_epoch(k)`。
  **直接 `for b in ds`（不经 `MegadataDataLoader`）不会推进轮号**（会告警）——这是一条已知边界；
- **生命周期（全包统一：close 只有一种语义——终态）**：
  `with MegadataDataLoader(ds) as dl:` 退出时 `close()`（之后迭代/查询明确报错，需重建实例）；
  训练间隙只想释放读头用 `ds.release()`（非终态，下一轮迭代自动重建）；
- **逃生门**（自担契约风险）：直接用 `torch.utils.data.DataLoader(ds, batch_size=None, collate_fn=lambda b: b)`
  可以跑，但会失去 teardown 轮号推进——**必须自行 `ds.set_epoch(k)`**，否则每轮数据顺序相同；
- **平台（spawn）限制**：Windows / macOS（Python 默认 `spawn`）下 `DataLoader(num_workers>0)`
  需要把 dataset 序列化给 worker，而 Rust 读头不可 pickle——`load_state_dict` 之后立刻迭代会在
  worker 启动时失败。`StreamingDataset.__getstate__` 会**丢弃已 seek 的读头**并告警，worker 内
  从该轮开头重读（与 `num_workers>0` 的既有轮级精度一致）；**批级精确续训请用 `num_workers=0`**。
  Linux（fork）不序列化 dataset，不受影响。

### 4.9 `RandomAccessBatchReader`（评估/调试专用）

```python
RandomAccessBatchReader(index_json_path, *, batch_size=None, max_seq_len=None,
                        world_size=None, rank=None, seed=42,
                        partition="round_robin", num_canonical_nodes=None,
                        predownload=None, epoch=0)
```

> 除 `index_json_path` 外全部为 keyword-only；`batch_size` / `max_seq_len` 未传时从
> manifest 读取。也支持 `options=LoaderOptions(...)`（§4.2），但其中的 `shuffle`
> **有意忽略**——本入口无置换表语义，按 idx 直取没有"顺序"可打乱。

`__getitem__(idx)` 返回的是**一个完整 batch**（`(batch_size, max_seq_len)`），不是单样本。
**不要**再套 `torch.utils.data.DataLoader(batch_size=N)`（会 batch 嵌套）；每次访问都 `seek + 读一个 batch`，
适合评估/抽查，不适合训练主力。

## 五、训练集成

### 5.1 为什么不要套 `torch.utils.data.DataLoader`

megadata 是**预批处理流**（batch 在构建期已定），与 torch DataLoader 的能力重叠且冲突：

| torch DataLoader | 与 megadata 的冲突 |
|---|---|
| `batch_size=N` | 会再批一次 → 维度多一维 |
| `num_workers>0` | 多进程 fork 与 Rust 后台线程/tokio runtime 冲突；**要用多 worker 请走 `StreamingDataset` + `MegadataDataLoader`**（reader 在 worker 内构造） |
| `shuffle` / `Sampler` | megadata 自带 shard 级 + 置换表打乱与 rank/worker 切分，叠加会破坏可复现性 |
| `collate_fn` / `pin_memory` / `prefetch_factor` | 已有等价能力（identity collate、DLPack 零拷贝、Rust 侧预取 + `predownload` 节流） |

### 5.2 DDP 训练循环

```python
import os, torch
from megadata import BatchStream, flatten_and_unpad, to_flash_varlen

world_size = int(os.environ.get("WORLD_SIZE", 1))
rank = int(os.environ.get("RANK", 0))

loader = BatchStream("out/sft/index.json", batch_size=BATCH_SIZE, max_seq_len=MAX_SEQ_LEN,
                              world_size=world_size, rank=rank, seed=42)

for epoch in range(num_epochs):
    for step, batch in enumerate(loader):
        input_ids = batch["input_ids"].to("cuda", non_blocking=True)
        labels = batch["labels"].to("cuda", non_blocking=True)
        cu = batch["cu_seqlens"]
        out = model(input_ids=input_ids, labels=labels, cu_seqlens=cu)   # 你的模型接 varlen
        loss = out.loss
        loss.backward(); opt.step(); opt.zero_grad(set_to_none=True)
```

### 5.3 断点续训

各加载器的 `state_dict()` 结构（都设计为可 `torch.save` 进 checkpoint）：

| 加载器 | 内容 | 恢复语义 |
|---|---|---|
| `BatchStream` | `{schema:3, seed, epoch, in_epoch_pos, manifest_fingerprint, topology}` | 置换表纯函数重算 + `seek_to_epoch_batch(epoch, in_epoch_pos)`（O(1)，几十字节） |
| `MixBatchStream` | 以上 + `{weights, base_weights, temperature, steps_yielded, sub_stream_cursors, rng_word_pos}` | 逐子流 seek 到各自 `(epoch, in_epoch)` + RNG 跳到 `word_pos`（O(1)）；权重与温度一并恢复（旧快照按 `weights` 当 base 兜底） |
| `StreamingDataset` / `MegadataDataLoader` | 前者透传引擎快照；后者 `{num_batches_yielded, dataset, tier1, resume_granularity}`（`tier1.epoch` = Tier-1 轮号，P2-9 由点号键 `dataset.epoch` 改嵌套，旧格式快照静默兜底） | 按快照重建 loader；`tier1.epoch` 回填 Tier-1 轮号（F-01）；`resume_granularity` 自述精度（`"batch"` = 可精确到批；`"epoch"` = 多 worker 下只精确到轮，恢复从该轮开头重读，方向为重放） |

四个入口的 **epoch 语义与访问代价**（P1-6 复核结论，实证口径）：

| 入口 | epoch 语义 | 访问代价 |
|---|---|---|
| `BatchStream` / `MixBatchStream` | 属性读 = 引擎游标当前轮（引擎层 break 后**不推进**，下轮从本轮第 0 个 batch 整轮重放，EOF 才推进） | ≈ 2 µs/次（FFI + 小结构拷贝；`state_dict` 只取 3 个小字段，**无**"每 step 物化整个 mixer state"的开销） |
| `RandomAccessBatchReader` | 构造期固定（`epoch=` 参数即访问轮），无 `state_dict`，改轮须重建 | 属性读，零计算 |
| `StreamingDataset` / `MegadataDataLoader` | Tier-1 **dataset 计数**（`_tier1_epoch`，唯一权威）：teardown 无条件推进；mode C 提前中止例外（= 一次重放 + 略过一轮） | 属性读（主进程计数）；`set_epoch()` 重语义（活跃会话中调用抛错） |

要点：

1. **恢复时用与原 run 相同的 `seed`、`world_size/rank`、`partition`**（弹性场景除外，见 §4.4）；
2. `load_state_dict` 之后下一个 `next()` 就是断点之后的 batch（Rust 侧有"代际栅栏"，会丢弃陈旧预取）；
3. **轮号由快照恢复**：`load_state_dict` 用 `state["epoch"]` 覆盖构造期 `epoch=`，恢复轮跑完后
   `epoch+1`——不会"从 epoch 0 重跑"（`num_epochs` 已在 v3 移除，轮数归训练脚本）；
4. 混合精度/优化器状态照常保存，互不影响；
5. ⚠️ **break 语义两层不同**（迁移注意）：引擎层 `for b in loader: ... break` 后 epoch **不推进**
   （EOF 才推进），下一次迭代**从本轮第 0 个 batch 整轮重放**；Tier-1（`MegadataDataLoader`）的 teardown 无条件推进，
   break 视为"该轮已消费"、下一轮**跳到下一轮**。需要"读一半接着读"的语义请在引擎层做
   （用 `state_dict()` + `load_state_dict()` 精确控制）；
6. **轮末快照自动归一化**：快照落在"轮内最后一个 batch 之后"（`in_epoch_pos == 轮长`，轮长整除
   `save_steps` 时常见）时，`state_dict()` 会按"下一个待产出位置"写成 `(epoch+1, 0)`（与
   `MixBatchStream` 耗尽子流归一化同口径）；旧版本写出的 `(epoch, 轮长)` 快照在
   `load_state_dict()` 里同样被归一化，不会在恢复时 `seek 越界`。`len()` 因此始终等于
   "本次迭代实际会产出的步数"（轮末快照恢复后是**完整一轮**，旧实现会返回误导性的 1）。

```python
ckpt = {"model": model.state_dict(), "optim": opt.state_dict(),
        "dataloader": loader.state_dict(), "epoch": epoch, "global_step": global_step}
torch.save(ckpt, f"ckpt_{global_step}.pt")

state = torch.load("ckpt_1000.pt")
model.load_state_dict(state["model"]); opt.load_state_dict(state["optim"])
loader.load_state_dict(state["dataloader"])      # 内部回填轮号 + seek 到断点位置
```

### 5.4 中断、取消与资源释放

- 导入 megadata 后，**首个实例构造时**会惰性安装 SIGINT/SIGTERM handler（幂等、链式调用前一个 handler，
  不吞掉框架自身的处理）；`MEGADATA_DISABLE_SIGNAL_HANDLER=1` 可彻底关闭；
- 阻塞在 IO 上时 Ctrl+C 也能在一个 batch 周期内退出，抛 `MegadataInterrupted`（`KeyboardInterrupt` 子类）；
- 主动取消：`loader.cancel()`（四种加载器 + `StreamingDataset` + `MegadataDataLoader` 均提供）/
  `builder.cancel()`。**取消是终态**：该实例（每实例取消令牌无 reset）不再产数据，
  需要继续训练请重建实例；
- **资源释放（全包统一：`close()` 只有一种语义——终态）**：
  - `close()`：释放底层读头并从信号注册表注销（幂等）；**之后 `__iter__` / `len()` /
    `state_dict()` / `get_batch` 全部明确报错**，请重建实例。所有持引擎对象
    （含 `StreamingDataset` / `MegadataDataLoader`）都支持 `with`：

    ```python
    with BatchStream("out/pt/index.json", batch_size=8, max_seq_len=4096) as loader:
        for batch in loader:
            ...
    # 或显式 loader.close()
    ```

  - `release()`（Tier-1 专有）：**非终态**——只释放"当前轮"读头（读头按轮重建），
    下一轮 `__iter__` 自动重建。训练间隙 / 长评估等资源敏感场景用它主动让出内存与下载线程：

    ```python
    ds = StreamingDataset(...)
    ...          # 训练一段
    ds.release() # 让出读头；之后仍可继续迭代
    ```

## 六、运行期行为、错误处理与环境变量

### 6.1 错误语义（不会静默挂住）

读取端的错误分三态（详见实现说明 §五.5）：

| 情况 | 表现 |
|---|---|
| 读完当前轮 | 迭代正常结束（`StopIteration`） |
| 用户取消（`cancel()` / Ctrl+C） | 阻塞中的取数抛 `MegadataInterrupted`（P6；取消是终态，见 §5.4） |
| 轮询超时（暂无数据） | 内部重试，不抛错 |
| **IO / 解压 / 数据损坏** | 抛 `OSError`，消息含 **shard 名 + batch 下标**，例如：<br>`megadata stream fatal error (no more silent retries): shard shard_00000.bin batch 0 read failed (file truncated / disk corrupted?): failed to fill whole buffer`（P2-2 起用户可见消息统一英文，注释与文档维持中文） |

- **本地读有有限次重试**：2 次、退避 50ms/200ms；瞬时半截文件/瞬时 EIO 可自愈，重试用尽才上报；
- **云读不叠加**：下载层已有 3 次指数退避（**首次退避即 500ms**，随后指数增长）+ 原子写 + sha256 校验；
  ⚠️ 两套重试参数不同（本地 2 次 50/200ms vs 云端 3 次 500ms 基期），排障时别按同一节奏预期；
- 缓存文件被篡改（bit rot）：开启 `MEGADATA_VALIDATE_CACHE=1` 时校验命中缓存并自动重下修复；
- **本地文件被篡改（bit rot）**：默认**不校验**（零开销）；`MEGADATA_VERIFY_LOCAL=1` 开启全量
  sha256 校验（结果按 size+mtime 缓存，同一文件只 hash 一次）、`=sample:P` 按文件概率抽样；
  校验失败报 `Checksum failure (local): …`，请重新复制/重建数据集；
- `shard 数 < world_size`、`batch_size/max_seq_len` 与构建期不一致、`index.json` 版本不支持：
  **在构造加载器时就报错**（带可操作建议），不会等到训练中途。

### 6.2 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `MEGADATA_CACHE_DIR` | `/tmp/megadata_cache` | 云文件缓存目录 |
| `MEGADATA_CACHE_LIMIT` | `256GiB`（支持 `K/M/G/T`，按 **1024 进制**解析；`0`=不限） | 超限按最久未使用（**mtime**，非 atime）驱逐——命中缓存时会 touch 刷新 mtime；Linux 普遍 relatime/noatime 挂载，**用 atime 会导致 LRU 完全失效**。**允许设得比工作集小**：被驱逐的文件在下次打开时会自动重新物化（只多付下载，不会读不出来） |
| `MEGADATA_VALIDATE_CACHE` | 关 | 命中缓存也校验 sha256（防 bit rot；代价是每次命中多一次读+hash） |
| `MEGADATA_VERIFY_LOCAL` | 关 | **本地数据集读的 sha256 校验**（F1）：`1`=全量（带 hash 记录的文件逐一校验）、`sample:P`（`0≤P≤1`）按文件确定性抽样；结果按 (size, mtime) 缓存——同一文件只 hash 一次，运行期零开销。失败即报 `Checksum failure (local)` |
| `MEGADATA_DISABLE_SIGNAL_HANDLER` | 关 | 关闭 megadata 的信号接管（交给框架） |
| `WORLD_SIZE` / `RANK` | — | `world_size=None` 时的自动探测来源（**回退到 env 时告警一次**，防单机残留变量静默分片） |
| `MEGADATA_STRICT_TOPOLOGY` | 关 | `1` = 禁止从 `WORLD_SIZE`/`RANK` 回退（未显式传参且 `torch.distributed` 未初始化时直接报错） |
| `MEGADATA_SKIP_DDP_CHECK` | 关 | 关闭 `MixBatchStream` 自然模式的 DDP 轮长检查（构造期静态判定 + 显式 `verify_ddp_consistency()`，见 §4.7） |

云路径（`http(s)://` / `s3://` / `gs://`）的取数链路：跨进程文件锁单飞 → 3 次指数退避重试（带抖动）
→ 写 `.tmp.<pid>` → sha256 校验 → 原子 rename。进程被 kill / 磁盘满 / bit rot 都不会产生"半截文件被永久信任"。

## 七、容量规划：选 shard 大小 / `cache_limit` / `predownload`

`python -m megadata.simulation` 不跑训练，按真实读取序（与 reader 同一套分区/置换纯函数）推演
**下载带宽 → 节点缓存 → 饥饿**，用来回答"参数设多少"。

```bash
# 单次推演
.venv/bin/python -m megadata.simulation out/pt/index.json \
    --world-size 64 --num-workers 2 --num-nodes 8 \
    --bandwidth-mbps 500 --cache-limit-gb 64 --compute-ms-per-batch 250 --predownload 16

# 扫描每节点缓存 = 2/4/8/16/32/∞ 个 shard，输出对照表
.venv/bin/python -m megadata.simulation out/pt/index.json --world-size 64 --sweep-cache
```

输出示例（节选）：

```
| 每节点缓存 | steps | 下载量 | hit_rate | starve_ratio | wall_time | p99 | gpu_util |
| 8×shard   | 1484 | 196.7MB | 0.008 | 0.992 | 96.0s | 250.0ms | 0.966 |
| ∞         | 1484 |   1.1MB | 0.997 | 0.003 | 96.0s | 250.0ms | 0.966 |
```

怎么读：

- `hit_rate` 低 + `starve_ratio` 高 ⇒ 缓存太小或预取窗口太小：先加大 `cache_limit`（把 `MEGADATA_CACHE_LIMIT`
  设到能装下"每节点 × 预取窗口 × shard 大小"），再考虑加大 `predownload`；
- 本模型下 **miss 必然产生等待**，所以 `starve_ratio == 1 - hit_rate`（模型假设见实现说明第九节）；
- `bandwidth_mbps` 是**每节点共享下行带宽**（MB/s，按 1e6 bytes）；`compute_ms_per_batch` 用你实测的
  step 时间（不含数据等待）代入；
- 调完回到真实训练用 `bench/throughput.py` 验证。

Python API：

```python
from megadata.simulation import SimulationConfig, simulate, sweep_cache
cfg = SimulationConfig(index_path="out/pt/index.json", world_size=64, bandwidth_mbps=500)
r = simulate(cfg)                 # SimulationReport
for label, rep in sweep_cache(cfg):        # [(档位标签, SimulationReport)]
    print(label, rep.hit_rate, rep.starve_ratio, rep.wall_time_s)
```

### 外部基线对比（2026-09-30，80 核机器 / 26 核 CPU 预算 / 同一份 jsonl + 同一个 bbpe 分词器）

PT 流式 packed 读（bs=16，msl=2048，有效 token 2,041,473,324）：

| 链路 | 预处理 | 读取 | 端到端 | 有效吞吐 | 峰值RSS(树) | 首批 |
|---|---|---|---|---|---|---|
| **megadata_rs (BatchStream)** | 328s† | **23s** | **351s** | **90.5 Mtok/s** | **0.60GB** | 0.01s |
| HF datasets (arrow 缓存 + DataLoader) | 644s | 119s | 763s | 17.1 Mtok/s | 29.8GB | 0.45s |
| PyTorch DataLoader (jsonl 现算) | — | 640s | 640s | 3.2 Mtok/s | 9.7GB | 0.37s |

SFT 变长监督批（bs=8，msl=2048，有效 token 312,629,683）：

| 链路 | 预处理 | 读取 | 端到端 | 有效吞吐 | 峰值RSS(树) | padding 浪费 |
|---|---|---|---|---|---|---|
| **megadata_rs (BatchStream)** | 88s† | **13s** | **101s** | **24.5 Mtok/s** | **0.60GB** | **0**（构建期 packing） |
| HF datasets (arrow 缓存 + DataLoader) | 102s | 311s | 413s | 1.0 Mtok/s | 38.0GB | 32.7% |
| PyTorch DataLoader (jsonl 现算) | — | 791s | 791s | 0.4 Mtok/s | 9.7GB | 32.7% |

要点与口径（完整说明见 `bench/out/compare_baselines.md`，每次运行自动重新生成）：

- PT 有效吞吐 megadata ≈ **5.3× HF arrow 缓存链路**、**28× DataLoader 现算链路**；端到端（含
  一次性预处理）≈ 2.2× / 1.8×。优势来源：构建期 tokenization+packing+zstd 压缩，读取端
  纯顺序解压切片，无逐样本 Python 开销、无 padding。
- SFT 差距更大的主因：基线 pad batching 浪费 32.7% 计算，且逐样本 collate 在 Python 侧；
  megadata 掩码在构建期完成，读取即拿 `(input_ids, labels, position_ids)`。
- 内存有界是硬差异：megadata 读取全程 0.6GB；HF 预处理峰值 30-38GB（含 26 个 num_proc
  子进程），基线过程数据都在进程树内存里过一遍。
- † megadata 构建期引用 phase9 §5.6 实测（同机、`RAYON_NUM_THREADS=26`）；HF 预处理为现场
  实测；DataLoader 无预处理生态（成本融合进读取）。
- 公平性：三链路用同一个 bbpe 分词器的 Python 包装（token 流一致，守恒校验逐位验证：PT
  首 window == 真值前缀、SFT 前 8 条 == 独立状态机复算）；megadata 原生路径在 Rust 内直连
  分词属于架构差异的一部分；HF/DataLoader 基线均按各自生态最佳实践实现，非稻草人；读取
  顺序 megadata → HF → DataLoader，首遍后输入全进 page cache（对 megadata 略不利）。
- 结论边界：以上是**纯 CPU 数据供给管线**的对比（不含 GPU 训练）；数据集完全装得进内存且
  已是 tensor 时，DataLoader 切片本身极快——megadata 的价值在超内存数据集、压缩 IO、
  确定性续训与构建期掩码/packing。

## 九、故障排查

| 症状 | 原因 | 处置 |
|---|---|---|
| `shard 数 (N) < world_size (M)` 报错 | 聚合粒度太粗 / `world_size` 太大 | 减小 `batches_per_shard` 重建，或降低 `world_size` |
| `batch_size 不一致：构建期为 X，加载期为 Y` | 加载参数与构建不一致 | 统一常量（构建/加载共用一个 `BATCH_SIZE`） |
| `max_seq_len 不一致` | 同上 | 同上 |
| `index.json 版本不受支持` | 用旧版本构建的数据 | 用当前版本重建数据集 |
| SFT 构建后 `total_shards=0` / 加载报 "no shard records" | `template_str` 为空（渲染出空文本） | 传对话模板；当前版本会发 `UserWarning` 提醒 |
| 构建报 `Build produced 0 shards (docs_read=…, docs_tokenized=…)` | 全部行被过滤：模板变量与数据 key 不对应（`messages` 数据配了只认 `conversations` 的模板）、输入为空或 PT 行缺 `text` 字段（F4：0 产出已从静默成功改为显式报错） | 检查模板变量与数据 key 的对应（§2.2）；检查输入文件非空且含相应字段 |
| `Checksum failure (local): …` | 本地数据集文件被篡改/损坏，且开启了 `MEGADATA_VERIFY_LOCAL`（F1） | 重新复制/重建数据集；确属误报可临时 unset `MEGADATA_VERIFY_LOCAL` |
| SFT 构建收尾 WARN `SFT truncation summary` / manifest 出现 `truncated_docs>0` | 有对话超过 `max_seq_len` 被 tail 截断；`all_masked_docs>0` 时还产出了 labels 全 −100 的废样本（F2） | 调大 `max_seq_len` 或清洗过长对话；核对训练目标不受影响 |
| SFT 构建收尾 WARN `Turn-marker injection summary` | user 内容里嵌入了 turn 标记文本，被掩码状态机当真实轮次（监督泄漏，F7） | 清洗/转义数据中的标记文本；核对 `docs_flagged_injection` 计数与样本 |
| 读到一半抛 `OSError: … shard … read failed` | shard 被截断 / 磁盘损坏 / 半截缓存 | 本地：修/重下该 shard；云端：清缓存重下（或开 `MEGADATA_VALIDATE_CACHE=1` 自动修复） |
| 迭代"卡住"没数据 | **老版本**会把 IO 错误当 EOF 静默重试；当前版本已改为报错 | 升级到含 `ReaderExit` 三态语义的版本；若仍卡住请附 `RUST_LOG=warn` 日志 |
| 训练步慢、GPU 空转 | 预取/缓存不足 | `python -m megadata.simulation … --sweep-cache` 调参；确认 `predownload ≥ 16` |
| 续训后 `len(loader)` 比预期小 | 正常：`len()` 是"下一次迭代实际会产出多少"（恢复后为剩余，F-08 统一口径） | 直接用它排 LR scheduler 即与真实步数一致；不要把它当整轮长 |
| 混采时报 `KeyError: 'labels'` | 异构 schema | 按 `"labels" in batch`（或 `batch["format"] == "sft"`）分支 |
| `update_temperature` 抛 `ValueError` | 有数据集 `global_stats.total_tokens == 0`，或权重非法 | 显式指定 weight / 用 `update_weights`；或重建数据集补上 token 统计 |
| 传 `shuffle="buffer"` 报 `ValueError` | v3 已移除 buffer 模式 | 换 `"permutation"`（超集）或 `"none"` |
| 续训后数据顺序与预期不符 | 换了 `seed` / `world_size` / `partition` | 与原 run 保持一致（弹性场景用 `relaxed` + `num_canonical_nodes`） |
| 单机训练莫名其妙被分片 | 环境里有残留 `WORLD_SIZE`/`RANK` | 清除变量或显式传参；`MEGADATA_STRICT_TOPOLOGY=1` 禁止 env 回退（F-14） |
| 直接迭代 `StreamingDataset` 轮号不推进 | 绕过了 `MegadataDataLoader`（C24-③） | 用 `MegadataDataLoader` 迭代，或手动 `ds.set_epoch(k)` |
| Ctrl+C 不生效 | 框架也在管信号 | `MEGADATA_DISABLE_SIGNAL_HANDLER=1` 交给框架，或检查 handler 链 |

## 十、FAQ

**Q：一定要用 `bbpe_tokenizer` 吗？**
构建需要（`tokenizer_path` 必填；自动推导 token ID 依赖它）；纯加载不需要。

**Q：能直接读 HuggingFace Tokenizer 吗？**
不能。`tokenizer_path` 指向 bbpe_rs 训练出的 tokenizer 目录；跨 tokenizer 复用数据集会使 token 含义不符。

**Q：为什么 `batch_size` 不能改？**
batch 在构建期已预打包进 shard（SFT 是 Arrow 行数、PT 是定宽读块）。要改只能重新构建。

**Q：一个 shard 里有多少 batch？**
`batches_per_shard`（默认自动 ≈128MB/shard）；加载端按 `num_batches` 展开，对使用者透明。

**Q：一轮读完后还能 seek 回去继续读吗？**
可以——读完（EOF）后 reader 线程保持存活等待 Seek，续训回退（`load_state_dict`）不会被破坏。

**Q：训练时需要 `pin_memory` 吗？**
不需要；如仍想要，在训练循环里对 batch 张量显式 `.pin_memory()`。

**Q：怎么把 `cu_seqlens` 用于 chunked prefill / 变长 attention？**
见 §4.6；三种 backend 任选，或用 `cu_seqlens_to_doc_ids` 自己构造 mask。

**Q：`RandomAccessBatchReader` 能用于训练吗？**
不建议（每次访问都 seek + 读，无预取/打乱/续训语义）；评估/抽查用它，训练用 `BatchStream`。

## 附录 B：常用常量建议

| 场景 | 建议 |
|---|---|
| `batch_size` / `max_seq_len` | 与模型/显存匹配；构建后不可改（改则重建） |
| `batches_per_shard` | `≈ 总 batch 数 / (world_size × 5~20)`；保证 shard 数 ≥ world_size |
| `predownload` | 默认 16；IO 抖动大时 32~64（内存 ≈ `predownload × batch 字节`） |
| `MEGADATA_CACHE_LIMIT` | `≥ 每节点并发预取 shard 数 × shard 大小 × 2`（先用仿真器扫一遍） |
| `seed` | 全 run 固定；续训不变 |
